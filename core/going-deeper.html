Going deeper

Skills, scheduled tasks, and file agents

Pocket card

  • A skill saves instructions you use repeatedly.
  • A scheduled task starts recurring work without you. Begin with ones that report back for your review.
  • A file agent such as Claude Code, Codex, or Antigravity works directly in a folder: it reads your files, edits them, and builds things from them.
  • GitHub stores the result, keeps every version, and can publish it as a website.

Come back to this page once a workflow is something you do every week, or once a project has outgrown the chat window.

Skills: save instructions you use repeatedly

A skill packages recurring instructions and supporting material so the same prompt does not have to be rebuilt each time. Meeting summaries are a good candidate, because you want the same structure, length, and points of attention every month.

If you work across more than one platform, keep the master copy of the instructions in your project home and adapt it for each tool.

Personal context portfolio

If you use several models, a short document about how you work saves repetition: your roles, recurring preferences, constraints, and writing style. Project instructions can tell the model when to read the relevant part.

The cost is upkeep. The document only helps while the important parts are current.

Scheduled tasks: let recurring work start without you

Once a workflow is stable, it can run on a schedule: a literature search every Monday, a digest of journal emails twice a week, a reminder with the material already prepared. Start with tasks whose output comes back to you for review. Tasks that send messages or change files on their own can wait until you trust the workflow.

File agents: Claude Code, Codex, and Antigravity

In a chat, you upload a file and the model answers in the window. A file agent works in the folder itself. It can read every file there, create and edit files, run what it builds, look at the result, and fix problems. Claude Code (Anthropic), Codex (OpenAI), and Antigravity (Google) are three versions of this idea. They began as tools for programmers, and the same ability is useful to anyone whose project is a folder of documents.

Very little technical background is required to start. You describe what you want in plain language, the agent proposes the steps, and you approve them.

An example: lecture notes to a teaching website

IllustrativeThe prompts below are reconstructed to show the pattern. The author's own prompts and screenshots will replace them.

I had a folder on my laptop with my eye emergencies teaching material: Word documents, slides, and images, all public teaching content with no patient information. I opened the folder with a file agent and asked for a website.

First request
This folder holds my lecture material on eye emergencies. Read all of it. Then propose a structure for a teaching website for residents: one page per topic, a consistent layout, and a short quiz at the end of each page. Show me the plan before you build anything.

The agent read the files, proposed a set of pages, and built them after I adjusted the plan. From there the work followed the loop in Running larger projects: one topic at a time, with my review before each page was accepted. Because the agent can see every file, a change to a shared element such as the navigation carries through all the pages in one request.

A later request
Compare the chemical burn page with my original Word notes. List anything in the notes that is missing from the page, and anything on the page that the notes do not support.

Where GitHub fits

GitHub is a service for storing a project's files with their full history. For a teaching site it does three jobs:

  • Storage. The project lives online as well as on your laptop.
  • Versions. Every change is recorded, so you can see what changed and return to an earlier state.
  • Publishing. GitHub Pages can serve the folder as a public website at no cost.

The agent handles the mechanics. You can ask it to "save this version to GitHub with a note about what changed" and it will. This site is built and published the same way.

The data rules apply to folders. A file agent on a personal account can read everything in the folder you open. Point it only at folders of public material. A public GitHub repository is visible to anyone, so check a folder for patient information, learner evaluations, and internal documents before it goes there.
